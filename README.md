# Khora

An event-driven, brain-inspired cognitive architecture in C++20.
LLM-free by design. Runs on one PC, no cloud, no telemetry.

Built by **Morphus** (an AI engineer-persona) for a single human operator.

## What this is — and isn't

Khora is **not** a chatbot, **not** a wrapper around a language model,
**not** a deep learning system. It is a substrate for cognition built from
binary hypervectors, an explicit co-occurrence graph, symbolic relation
extraction, and competing intrinsic drives. It thinks in patterns, not tokens.

That means: Khora will never generate fluent prose about arbitrary subjects
the way an LLM does. It also means every capability it has is mechanistically
transparent, runs on commodity hardware, and is yours alone.

## Current state

**v0.115.0 — 23 modules, 16,877 lines of C++20 (22,503 with tests and benches),
20 test binaries under ctest, all green.** Rebuilt from a module-by-module read
of the source; see [docs/AUDIT-2026-08-19.md](docs/AUDIT-2026-08-19.md) for the
evidence and [CHANGELOG.md](CHANGELOG.md) for what changed and what failed.

**BUILT is not the same as WIRED, and the table below says which.** The sparse
`Sdr` substrate and the `TemporalMemory` are built, tested and benchmarked —
and `khora_main.cpp` does not reference either of them. The running binary is
still entirely on the dense `Glyph` path and still uses `PredictiveColumn` for
sequences. They are organs that have not been put in the animal yet. The same
has been true of the Synapse Bus for 115 releases.

### What has been measured

The project rule is that nothing is claimed unless it has been built, run and
observed. These are the numbers, including the ones that went the wrong way.

| Claim | Measurement |
|---|---|
| Sparsity, not dimensionality, makes subsampled matching work | False-match rate at s=24/theta=12: **dense 0.5764**, **sparse 0 in 400,000** |
| Per-cell context solves sequences a pair-encoding cannot | Sequences sharing a middle: **temporal memory 100%** at N=2,3,4,6; dense chain **50.0 / 33.3 / 25.0 / 16.7**, exactly chance |
| Categories can be overlap rather than stored edges | 207 WordNet categories, frequency-matched negatives: **code 0.6168** vs affinity 0.5298, frequency 0.5199, random 0.4947; paired **161-42, z = 8.35** |
| **For exact recall, a trigram table wins** | Real books: **trigram AUC 1.0000**, temporal memory 0.9981. The machinery only wins past ~25% input corruption — and n=3 is one of the few depths where English repeats at all |
| **Deep context is a dead end on prose** | Share of n-word contexts that ever recur, 7.66M tokens: n=1 **66.9%**, n=2 **30.7%**, n=3 **13.5%**, n=8 **0.32%**. A 319x increase in corpus moved n=8 from 0.00% to 0.32% — it saturates. Distinct contexts per token at n=8 is **0.996** |
| **A population of specialists loses to one model** | Four arms, one budget: monolithic **0.978** held-out burst vs partition 0.992, competition 0.998, selection 0.985, at 2-7x the runtime |
| **Greedy novelty-seeking is a trap** | Scores **1.0000 surprise-remaining** at every signal-to-noise ratio — learns nothing, spends 92-98% of attention on static. This was Khora's stated Soma design |
| **Synaptic pruning did not pay** | Measured in two regimes, reverted |
| **The extracted taxonomy is mostly false** | Ligature is-a relations, measured |
| **A bounded predictor beats an unbounded n-gram** | 1.8M tokens, held out: ContextTree **8.45%** under a 300k-node ceiling vs bigram 7.66% with every successor kept. Accuracy rises with the order chosen — 7.8 / 12.4 / 19.8 / 26.9 / 40.0 / 85.7 — because the order is picked by measured reliability, not depth |
| **Depth is not reliability** | Choosing the longest context seen made accuracy FALL where the traffic is (order 1 14.9%, order 2 13.9%, order 3 11.9%) and lost to a bigram outright |
| **10,000 lines of certified code in ~1.2 seconds** | The mandate is 10,000 lines in 30 s (333 lines/s). Every line comes from a program that passed every visible case AND every held-out case drawn longer than any it saw. Measured across four runs: **4,749 / 8,350 / 8,525 / 9,496 lines/s -- 14.2x to 28.5x the target.** The rate has a wide low tail and the counts do not, so both ends are quoted rather than the best. At fixpoint **~1,506 of 2,000 certified (75.3%)** against a spec whose cases span lengths 1-11 and whose holdout runs 13-16. Peak pool **0.2 MB per shard** |
| **"30 programs certified and wrong" is 0** | The counterexample arm reported 30 of 60 sampled tasks carrying a certificate and a counterexample at once, for several cycles, and counting them taught nothing. Printing them took one line. **All 30 were defects in the measurement.** 18: the task generators computed `x*k` in unbounded int64 while every value the system produces saturates at 1e9 -- on the 1e9 edge probe `mul(x, 5)` is the correct program and the reference demanded 5e9. 4: length overfits the case range could not see. 6: `Proof::Tested` results, which the system already labels untrusted, counted under a heading saying "certified". 2: the generator capped its own output at 64 elements where `Op::Range` caps at 512, so `range(x)` -- the right program -- returned 512 where 64 was wanted, on an input no case ever contained. **Fixed: 0 programs that claimed to generalise are wrong**, across 300 probes and 6 refinement rounds each |
| **Copy-on-write beat a reader-writer lock by 10.6x** | A shared library behind a `shared_mutex` held a READ lock for the whole search, so one writer stalled 24 workers: 76.95 s and 1.20x scaling. An immutable snapshot behind an atomic pointer: 5.79 s and 12.95x. Sharing then wins on BOTH axes -- 1099 certified against 993 |
| **Iterating to fixpoint lifts 55.0% to 64.8%** | A single pass attempts each task once, so a task that is trivial once some component exists fails when it comes first -- a fact about scheduling, not solvability. Rounds certify 1100, 175, 21, then 0. It TERMINATES: a round that certifies nothing cannot be followed by one that does |
| **Constraints are the quality knob** | 6 visible cases: 1296 certified, 333 memorised. 12 cases: **1404 certified, 249 memorised**. More constraints raise true certification and cut false positives at the same time |
| **An evolved operator TIES a one-line baseline — and the bench says so** | WordNet co-hyponymy through Plexus, held out, scored the way the relation is actually posed: Ribosome **3.530%** (40/1133) vs top-associate **3.442%** (39/1133). A two-proportion test cannot separate them, and the bench prints INDISTINGUISHABLE rather than a ranking. Two earlier reports from this bench — a 0.353-vs-0.177 "win" (4 hits vs 2) and a 3.18-vs-3.44 "loss" (36 vs 39) — were both inside the noise and are withdrawn |
| **Percentages without counts hid three wrong conclusions** | An adversarial audit found every difference this bench reported was within noise. Every rate now carries hits/n and a 95% Wilson interval, and the verdict line says INSIDE THE NOISE when a z-test cannot separate the leader from the runner-up |
| **Only 1.3 of 5 instructions in a genome were alive** | With a fixed output register, 27% of random genomes were pure identity and the behaviourally distinct space was ~384 programs — enumerable exhaustively in seconds. Reading out the LAST register written instead: **2.241** live instructions, **0.0%** pure identity, with no prior toward composition added |
| **Hypernymy is not in a co-occurrence graph** | Under class-balanced fitness a constant scores 1/k = 0.667%; the evolved champion scored **0.793%** against a majority-class baseline of 5.65%. Giving it neighbourhood intersection and second-order kinship moved it off the constant and made accuracy FALL. Nothing above the constant floor exists to be found |
| **A closed instruction set cannot search a hypervector space** | One-instruction target `bind(from, ROLE[57])`: 2,048 births, **0.000** of 1.0. Every wrong role is orthogonal to the right one, so the landscape is flat with one invisible needle. With graph senses, same budget: **1.000** |
| **Solving problems made later problems solvable — 185 against 138** | An open-ended ascent: tasks composed from verified solutions, so the curriculum escalates with capability instead of running out. Each tier run TWICE from identical specifications, once with the library carried from every earlier tier and once from empty. **185 verified carrying it against 138 from empty**, over fifteen tiers, ending because two consecutive tiers verified nothing rather than because the budget ran out. From tier 9 the empty arm verifies almost nothing while the carried arm keeps going |
| **Khora writes 13 of its own 22 primitives -- and "irreducible" was too strong a word** | Each primitive is removed and the system asked to rebuild it from the rest, then checked against the REAL implementation on 1,000 probes. **13 rebuilt, 13 of 13 agreeing on 1000/1000**, several through LEARNED library entries: `sort = append(min(x), lib1(x))`, `max = head(rev(lib6(x)))`, `len = sum(member(x, x))`, `mulk_2 = add(x, x)`. The other nine were called *provably irreducible*. **That claim was wrong.** This bench had the same defect as the other two -- training cases at lengths 0-6, holdout at 7-12, disjoint -- and fixing it moved `sort` OFF the irreducible list and `count_0` onto it. The count is unchanged at 13 and 5x the search budget does not move it, but a label that changes when you fix the specification generator describes the generator, not the instruction set |
| **The ascent ended on the CURRICULUM, not the solver -- and fixing that took it from tier 15 to tier 20** | Tasks are random compositions of atoms, kept only if they do not collapse to something an atom already computes. The keep rate fell to **0.7% by tier 15** (1,611 drawn, 11 kept) and from tier 12 the generator could not fill a tier at all. Three attempts to push the ceiling from the SOLVER side all landed inside noise: search pool 30k to 60k **+7 of 185**, admitting each answer's largest subexpression **+1**, mining subexpressions recurring across two or more answers **-1**. The cause was absorbing states -- `sum`, `len`, `take3` funnel into the singleton and the empty list, after which `sort`, `rev`, `pos` are identity. Five length-preserving, position-dependent atoms (`rot1 scan altneg idxmul ziprev`) have no absorbing state: **tier 15 to tier 20, 185 to 220 verified**, tiers full through 16 |
| **It can write functions of more than one argument** | Until now a `Case` held one input, so EVERY program this system could express was a unary function of one integer list -- the deepest limit in the tree, and the reason "writes anything" was false for a reason no amount of search speed touches. Arguments are now first-class leaves: `f(x, y) = append(x, y)` is synthesised from four examples, generalises to an unseen pair, and is proven to actually READ the second argument rather than pass by coincidence. It emits with the right parameter list in all 14 backends and is executed in six. The emitter's `op_fn` defaults to `kh_id`, so an unhandled argument node would have bound argument 1 to argument 0 in source that compiles and reads correctly -- handled explicitly instead |
| **ALL FOURTEEN backends executed and byte-identical against the certificate** | Not emitted -- COMPILED, RUN, and diffed line by line against `Recipe::apply`: **Python, JavaScript, TypeScript, Go, Rust, C++, C#, Java, Kotlin, Swift, PHP, Haskell, Lua, Ruby.** 16 recipes x 9 inputs, three recipes taking TWO arguments with argument 1 the NEXT input so a program that ignores it cannot pass by luck, three inputs longer than the 512-element bound where the interpreter clamps. Lua and Ruby run as real Lua 5.4 and CRuby 3.4 compiled to WebAssembly; the rest on native toolchains. Nothing is counted for being emitted -- Go was written as `package kh` and could never run while the harness printed a line count for it, and the `php` on PATH was a different tool wearing the name |
| **It can be TOLD a rule now, not just born with two** | The audit found formal reasoning absent -- no unification, no resolution, no SAT or SMT. The nearest thing was `Ligature::deduce`, whose two inference patterns are written into the C++, so Khora could not be told "a thing is fragile if it is made of glass and is thin" and could not use a rule it read. `logos::Engine` is Horn clauses with unification and backward chaining -- SLD resolution -- returning every binding that satisfies a goal AND the derivation that produced it. This is a different paradigm from the rest of the system on purpose: hypervectors are very good at "these things go together" and cannot express "for all x, if P(x) then Q(x)". 30 checks, including the three defects that make a resolver look right and be wrong -- variable capture across two uses of one rule, left recursion, and proving things that are false |
| **The optimisation I wrote to handle left recursion was what broke it** | The resolver carried a repeated-goal check, on the reasoning that `ancestor(?x,?y) :- ancestor(?x,?z), parent(?z,?y)` loops without one. Under exactly that rule the subgoal keys identically to the parent goal -- both have an unbound second argument -- so it refused the recursion it existed to permit. Three-step ancestors failed and two of three descendants were found, while the RIGHT-recursive form passed throughout, which is the signature. Doing it properly is tabling; the depth bound already guarantees termination, so the check is gone |
| **It can learn what its actions are worth -- 0.677 against 0.409 for the policy it replaces** | The audit found reinforcement learning entirely absent: no value function, no policy, no TD error, no bandit, no exploration rule; "reward" appeared only in comments. Volition scores every act as `drive pressure x affinity`, where affinity is a constant a human wrote down -- so Khora could not notice that an act it is told serves Curiosity has never once paid. `telos::Valuer` estimates what each action RETURNS per context and selects by UCB1. On a contextual bandit where the best action differs by context: **learned 0.677, the fixed hand-tuned policy 0.409, random 0.353, oracle 0.788 -- 71% of the gap to a perfect chooser, closed.** UCB rather than epsilon-greedy because Khora takes hundreds of decisions, not millions, and a fixed exploration rate spends a small budget on actions already known to be bad. Persisted from the start rather than added later |
| **Khora can see now -- 75.4% against a 49.2% baseline** | The audit found perception entirely absent: not one reference to a pixel, bitmap, camera or colour channel in the whole tree; every "image" meant the process's own executable image. It needed no new substrate. The Lattice is a 10,000-bit hypervector algebra, and an image encodes into it as `bundle over cells of bind(place, level)` -- so every faculty already built on Glyphs works on images unchanged. Four synthetic shapes at random positions, sizes and 4% pixel noise, test set from a disjoint seed: **retina 75.4%, nearest-class-mean on raw pixels 49.2%, chance 25%** |
| **Both of my rationales for the encoder were wrong, and the test said so** | The header argued pooling to a coarse grid buys translation tolerance. Measured: a one-pixel shift gives **0.880 per-pixel against 0.779 coarse** -- the opposite. It then argued pooling buys noise robustness instead. Measured under 10% noise: **0.794 per-pixel against 0.759 coarse** -- wrong again. The grid sweep settles it: **4x4 55.8%, 8x8 52.9%, 16x16 64.2%, 32x32 75.4%.** Pooling is a pessimisation and the default is now one cell per pixel. A third defect fell out on the way: random per-level bit flips COLLIDE, so the intensity scale only spanned to 0.25 similarity instead of 0; a permutation gives disjoint blocks and exact linear grading |
| **Planning was absent; now it exists, and it says the knowledge is thin** | The audit found no planning capability anywhere: Volition scores one step greedily, with no lookahead, subgoals or decomposition, while 19,475 typed causal relations sat unused for it. `Ligature::plan_to` chains BACKWARD from a goal -- `deduce` only ever went forward -- beam-searching over causes, refusing cycles, scored by the WEAKEST link because a plan is worth no more than its least-supported step. Exposed as `plan` and `plan_yield` |
| **94.7% of the causal layer is a single sighting** | Unfiltered, the new planner reaches 100% of goals in one step and 48.5% in two. Those chains are real paths and worthless: asked for `war` it returns `annual -> cannot -> him -> way -> war`, every link asserted **once**. With a support floor of two the same measurement gives **7.25% / 0.75% / 0%**, and the profile says why -- **2,350 causal triples seen once, 48 twice, 84 three-to-nine times, none ten or more.** The reasoner is sound; what it has to reason over is not. That is a far more useful result than a planner that looked like it worked |
| **Ligature had no test at all** | 400 LOC holding 19,475 relations in the live system, untested, while much smaller modules had several. It now has 24 checks over is-a transitivity and its depth bound, additive support, both query directions, property inheritance, causal chaining, planning, the support floor, cycle refusal, and the self-measurement -- each on a graph small enough that the right answer is obvious by inspection, so none of them can pass for the wrong reason |
| **A third of the codebase was built, tested, and never ran** | An audit of every module against `khora_main.cpp`: **techne (5,376 LOC), ribosome (637), synapse (147) and governor (317) are constructed by nothing.** The largest module in the repository -- program synthesis, fourteen language backends, certified answers -- was unreachable from the system it belongs to, which had 94 tools and not one that could write a program. Now wired: **`synth`** takes examples, returns a program with its proof state and source in any of the fourteen languages; **`synth_library`** shows the vocabulary; both share a library persisted under `data/`. Asked for `1,2,3=3,2,1`, the running system answers `rev(x)`, GENERALISED on a held-out case, with the Python. A capability the system cannot invoke is not a capability the system has |
| **And it now survives a restart: 21 of 40 to 31 of 40 across a process boundary** | The learned library was built, filled and DISCARDED at process exit -- nothing about programming compounded across runs, so a system meant to improve itself forgot between sessions. `Library::save`/`load` write it as text with operations NAMED rather than numbered, because this class has already shipped two defects caused by an index that meant something else later and an enum ordinal on disk is that mistake with a longer fuse. Measured: one process solves **21 of 40** fixed tasks cold, trains on 120 disjoint ones, saves 73 entries; a **second process** loads them and solves **31 of 40** of the same fixed tasks. The round trip is checked by FUNCTION, not by parse -- every entry must compute the same thing afterwards |
| **It does improve itself -- 22 to 38 against a bar that cannot move, and now loses NOTHING** | 96 tasks drawn ONCE from a fixed seed, never regenerated, never filtered against anything learned, never admitted to a library. Between measurements the system trains on a DISJOINT stream. **22 of 96 at the start, 38 after 864 training tasks, with the empty-library control at exactly 22 at every stage.** **16 gained, 0 lost** -- the last regression is gone. By depth: d2 12->13, d3 8->11, d4 2->8, d5 0->5, d6 0->1. Deterministic: the same run twice is byte-identical |
| **Three searches at once, tier 20 to tier 29** | Forward, bidirectional, and library-free were run one after another although none depends on the others -- spending the time budget three times for one answer. `solve_one` runs them concurrently and resolves by a FIXED preference order, never by who finishes first, so the answer stays a function of the specification rather than of the scheduler (checked: identical output across runs). | **Removing the library's regression was worth more than the library** | A library is a vocabulary AND a haystack -- every entry is another level-0 candidate for a bounded pool -- and `sort.delta`, two operations deep, was solved with an empty library and NOT with a 96-entry one. `construct_best` keeps the better of with-library and without, paying a second search only on tasks that already failed. Losses fell 3 to 1 and the total went **28 to 38**: the fix was worth **+10**, more than the entire library gain before it. The one remaining loss is a program that CERTIFIED -- passed every case and the holdout -- and failed the external 200-probe check, so the fallback never fired |
| **The benchmark's own case lengths were hiding 22% of the capability** | `make()` drew training cases at lengths 1-5 and holdout cases at 7-11 -- **disjoint ranges**. Any program whose behaviour depends on length passed every visible case and failed the holdout BY CONSTRUCTION. Measured on `idxmul`: the search produced `add(x, mul(x, range(5)))`, exactly `x*[1..5]`, exactly right for every length the cases contained. More cases did not help -- they were all short. Widening the cases to lengths 1-12 solved it outright: `add(x, mul(x, range(100)))`, 20/20 and 5/5. Tasks reported as beyond the ceiling were never beyond it. The fixed bar went **18 to 22 at base**, depth-2 from 10 of 16 to **12**, and depth 6 stopped being zero |
| **Solving for the operand instead of enumerating it: 16/20 to 18/20 on 19% fewer nodes** | The binary sweep tries every PAIR -- `end^2 x |ops|` -- which is what puts operation-depth 4 out of reach before a 200,000-node pool fills. But for an invertible operation the second operand is DETERMINED by the target: if the answer is `mul(a, b)` then `b` is `target / a`, and there is nothing to search for. A closing pass computes the required operand for each pool node and looks it up, **O(pool) per operation instead of O(pool^2)**, reaching one level deeper than the sweep that built the pool. On the fixed task set: **18/20 against 16/20, on 137,991 candidates against 169,437**. Every hit is re-verified forward, because `zip` cycles its shorter operand and an inverse that looks exact by construction can still be wrong |
| **Better search made the library a liability** | On that same fixed set the arms INVERTED: plain construction 18/20, construction with a learned library **16/20**. | **The residual ceiling is ONE wall: search reach, not expressibility** | Breaking the fixed 96-task bar down BY DEPTH: depth 2 solves 10 of 16 and learning adds nothing; depths 3-5 hold every gain (7->9, 1->3, 0->3); depth 6-7 is zero before and after. Everything is expressible; the search cannot reach it. A task labelled depth 2 in ATOMS can need six operation nodes, so the benchmark's depth labels understate the real depth by up to 3x |
| **The +39% is a net: 8 gained, 1 LOST** | Itemised, the library breaks a task it could solve without one. `sort.delta` -- literally `Delta(Sort(x))`, two operations both in the set -- is solved with an empty library and unsolved with a 96-entry one, because every entry is another level-0 candidate competing for a bounded pool. The two axes compose, both plateau, and neither alone sets the ceiling -- which is why raising the library budget 5x bought exactly one task |
| **Raising reach is nearly free; raising the curriculum is not** | A 2x2 on the same ascent. Adding `Op::ScanMax` and `Op::ScanMin` -- the running forms of `Max` and `Min` -- **costs nothing in outcomes: 232 vs 192 at tier 29, identical to baseline.** Adding the `cummax` ATOM costs **232 to 137** without those operations and **232 to 211** with them, so expressibility recovers 74 of the 95 lost and the residual 21 is the intrinsic price of a harder curriculum. Acting on that, `Op::Eq` and `Op::Lt` were added too -- `Gt` existed alone, and with masking and counting the comparison set makes conditional logic expressible. Four new operations, and the ascent is still **232 vs 192 at tier 29** to the digit. The honest caveat: free in OUTCOMES, not in candidates -- the fixed task set explores 137,991 to 154,958, 12% more search for the same 18/20 |
| **Speculating ahead: tier 23 to tier 28 in the same 300 s** | `solve_one` uses three cores; the task loop stays ordered because admission is task-by-task and that is where compounding lives -- so **21 of 24 cores were idle**. The first attempt was SLOWER (tier 15) because it re-ran every speculative miss, and at deep tiers most tasks are unsolvable, so each was solved twice for nothing. Retrying only when the library actually moved is the whole difference |
| **"The curriculum saturates" was the generator giving up -- tier 29 to tier 40** | The ascent ended because its task generator could not fill a tier, and that was measured correctly and diagnosed wrongly for several cycles. The budget was `per_tier * 40` -- 1,600 draws for forty tasks -- and at tier 29 the keep rate is about two in sixteen hundred, so it hit the cap and reported saturation. But a draw is a composition and twelve probe evaluations: microseconds, against the tens of seconds the tier then spends being SOLVED. Raising the budget to 80,000 draws: **tiers stay full through tier 34 and the ascent reaches tier 40**, ending on its stopping rule -- **271 verified against 223**, up from 232 against 191. The deep tasks existed the whole time; nothing was looking for them |
| **Curriculum depth and solver reach must be raised TOGETHER** | At tier 29 the generator draws ~1,610 tasks to keep two, so the ascent ends on the curriculum. The obvious lever is atoms outside the span of the existing ones -- measured with `dedup`, `cummax`, `rank`, `rotk`, `digitsum`: **137 verified against 118 at tier 25, versus 232 against 192 at tier 29 without them.** A third of the capability, gone. An atom outside the ATOM set's span is usually outside the OPERATION set's span too, because both are the same family, and a task built from an atom the solver cannot express is not harder -- it is impossible. The criterion is narrow: an atom must be outside the span of the other atoms and INSIDE the span of the operations. The five that worked (tier 15 to 20) are exactly that |
| **A wider gap can mean the baseline got worse** | Gating learned atoms on behavioural novelty was re-tested after the case-length fix, `construct_best` and `solve_one` had moved this bench a long way -- a rejection carries a profile with it and expires when the profile does. It did not expire. **admit first-come: carried 232, empty 192, gap 40, tier 29. Novelty-gated: carried 231, empty 175, gap 56, tier 26.** The gate WIDENS the gap by 16 and is still rejected, because the widening is entirely the control falling 192 to 175 while the carried arm does not move -- and three tiers of depth are lost to the extra search a more diverse atom set costs. Reporting the gap alone would have called this a 40% improvement |
| **A self-generated curriculum cannot demonstrate unbounded self-improvement** | The ascent poses tasks built from what it has already solved, and a task counts only if it differs from every atom -- so enriching the vocabulary raises the bar for what counts as a problem at the same moment it raises the ability to solve one. Measured three ways: admitting every solved program as a primitive gives **tier 20, 220 vs 191**; admitting only behaviourally NOVEL ones -- better engineering -- gives **tier 16, 130 vs 117**; novel and non-absorbing gives **tier 18, 175 vs 161**. Improving the vocabulary moves the yardstick it is measured against. This is a property of the INSTRUMENT, and it is why no amount of work here will show an unbounded curve: that needs a fixed external task set hard enough to reward a richer vocabulary, which does not yet exist in this tree |
| **A library is a haystack as well as a vocabulary** | A 2x2, each cell the carried-minus-empty gap inside ONE run. 19 atoms: budget 32 gives **185 vs 138**, budget 96 gives **174 vs 138** -- the bigger library makes it WORSE. 24 atoms: budget 32 gives **214 vs 191**, budget 96 gives **220 vs 191** -- the bigger library makes it better. Every entry is another level-0 candidate, so the right size is a function of how diverse the problems are and not a constant to tune once. The richer atom set also DILUTES reuse: per-task library lift falls from 9.1 points to 4.0, because tasks that share less structure reuse less |
| **A learned library is a vocabulary, not a lucky reordering** | Counting live `Call` nodes in the answers separates the two, and the library is IN essentially every deep answer: at 20 tasks a tier, `used lib` tracks verified almost exactly from tier 3 on. Chained calls -- `lib_j(lib_i(x))`, the composition the whole compounding story rests on -- were 4 across an entire ascent until recipes were compacted; they are now routine (2, 6, 4, 3 in the first tiers that admit them) |
| **A recipe was carrying its entire search pool** | `Recipe::apply` evaluated EVERY node the enumeration ever considered and returned one of them, so a ten-node answer found in a 15,000-node pool cost ~1500x what it should -- on every verification probe, every library call, every emitted program. Dropping what the root cannot reach: tier 2 **29.8 s to 0.7 s**, verification per tier **26.1 s to 0.0 s**, the whole fifteen-tier ascent **240 s exhausted at tier 5 to 32.7 s complete**. Identical answers |
| **I parallelised the 13%** | Before that fix I built block-parallel search, a persistent worker fan, adaptive and growing blocks -- and measured no speedup at any width. Timing the phases instead of theorising about them: forward search 3.5 s, bidirectional 0.2 s, **verification 26.1 s**. Amdahl had capped the entire effort at 13% before a line of it was written. Width 1 and width 21 came out 30.2 s and 30.7 s: the parallel path RAN, and it did not matter |
| **I built the paradigm Khora rejects and raced it -- the substrate wins by 30 points, then loses by 11** | The banner reads LLM-free and the audit found no matmul, no tensors, no autograd anywhere in the tree. A design position never measured against the thing it rejects is a preference, so `khora::descent` is a two-layer perceptron with hand-written backprop (worst disagreement against finite differences **1.40e-10**) raced against the retina on the SAME generator and the SAME disjoint 240-image test set. I ran it once at 160 training images -- hypervector 75.4%, MLP 58.8% -- and nearly published that. It is an artefact of the training-set size. Across the regime: at 5 per class **62.1% vs 31.7%**, at 20 **72.5% vs 47.5%**, at 80 **75.0% vs 72.1%**, at 320 **77.9% vs 89.2%**. The crossover is between 80 and 320, and adding data buys the MLP 57.5 points against the hypervector's 15.8. Khora learns a few examples at a time and never has three hundred labelled instances of anything, which is precisely the regime where the substrate it already has is the better choice -- now measured rather than assumed |
| **The extractor everything reasons over had no ground truth -- and it was in the tree the whole time** | `extraction_bench` graded relation quality with a 56-word blocklist and reported **5.3% error** on output like `justice is-a interest(5)`, `man is-a thing(3)`, `body is-a held(1)`. Its header said there was no ground truth for "is this relation true"; `data/eval/wn_categories.tsv` -- 3,031 WordNet categories over 35,767 words -- was already there, used by two other benches. Scored against it, the whole extractor gets **2.16% [1.58, 2.94]** against 0.50% chance. Then a pattern mask made each rule measurable alone, and the answer is not subtle: **copula 1.89% [1.34, 2.65] against Hearst 6.84% [3.51, 12.91], intervals that do not overlap.** The copula is 56% of everything produced. Two of the three Hearst frames were missing and one of them, `X and other Y`, is now the best rule in the extractor at 7.89%. `can` was the only modal absent from the stopword list, and `is-a(she, woman)` was the strongest is-a triple in the graph, asserted 42 times |
| **A 3.6x precision ratio, acted on, did not survive held-out validation -- and the fallback claim was the reverted change** | Every consumer filters on support, so weighting one Hearst sighting as three would let every existing floor prefer the better evidence with nothing else changing. On 29 books the ratio was not derived from: **6.98% [3.24, 14.40] weighted against 5.88% [2.72, 12.24] unweighted.** Reverted -- it would have cost `support` its meaning for a difference inside the noise. Then I recorded the consolation prize as "27 surviving triples become 102", which was the WEIGHTED graph reading a floor of 2 that a lone Hearst sighting cleared by itself. Unweighted it is 32. The result I fell back on was produced by the thing I had just deleted |
| **Khora had no idea what a noun was -- 61.0% recall, 94.2% precision, no tagged data anywhere** | An audit found no syntactic analysis in the whole tree: no tagger, no chunker, no parser, no notion that a token has a grammatical category. That is why the extractor asserted `is-a(man, social)` from "man is a social being" -- it takes the last content word of the noun phrase as the head, which is right, and cannot tell whether that word is a noun. `khora::taxis` counts what came before each word over the same books and reads a category off the counts. | **Both obvious rules for it were wrong, in opposite directions, and the threshold is printed rather than asserted** | Argmax over the three context counts is useless: an adjective follows a determiner far more often than it follows "very", so the largest count is always the determiner one. Measured, it cut **8.0% of known-bad objects against a 7.8% base rate** -- no discrimination at all. Reading the marked evidence first instead reaches 94.3% recall and calls **38% of certain nouns adjectives**, because over eight million tokens almost anything follows "so" twice. I also had the reason for that cost wrong -- assumed it was words below the evidence floor, added a lenient mode, and it changed 38.4% to 38.3%. The answer is a ratio, and `extraction_bench` prints the whole curve. **Maximising the discrimination ratio would have chosen 0.25 and been wrong**: it rewards cutting almost nothing |
| **And the bar I built cannot see the fix, which is worth more than pretending it can** | With the veto the graph goes from 12,870 triples to 11,940 and WordNet IS-A precision reads **2.16% either way**. That is a property of my harness, not the veto: a triple is decidable only when its object is a WordNet category name, and every category name is a noun -- so the decidable subset is nouns by construction and a rule that removes non-nouns has nothing to remove inside it. `is-a(man, social)` was never in it. One reference set can see the gain and the other can see the cost, and neither can do both |
| **The live graph was still built the losing way -- built and not wired, again** | `extraction_bench` has measured per-sentence extraction beating document-at-once for a while. `plexus_forge`, which is what actually writes the archive the runtime loads, was still tokenising whole documents -- so the extractor, which scans five words past a verb for its object head, walked into the next sentence. That is where `is-a(man, weber)` came from. The forge now reads sentences, builds a tagger in a first pass and extracts with it in a second. On the live graph `man` goes from **animal(7) weber(4) creature(4) social(3)** to **animal(9) being(5) thing(5) creature(4)** -- all four correct -- and `body is-a row` falls from 16 to 4 |
| **And the error I built a part-of-speech tagger for never needed one** | `is-a(man, social)`, from "man is a social being", is the case that justified the whole module. It survived the tagger. The reason: `head_after` ended the noun phrase at the first non-content word, and **"being" is on the extractor stopword list** for its participle use, so the phrase ended at "social". That list does two jobs -- is this token a concept, and where does a noun phrase stop -- and it is right for the first and wrong for the second. Separating them fixed the example outright, with or without a tagger. **Then I over-corrected**, dropped the candidacy check along with the terminator, and the next forge produced `is-a(force, same)` and `causes(light, very)`. One wrong answer swapped for the other; the live graph is what caught it |
| **Adding auxiliaries beat the tagger I had just calibrated, on both axes** | Degree adverbs only find GRADABLE adjectives: `social` has 232 determiners and 2 degree adverbs on this corpus, `held` 37 and 1. Participles have their own marked context and it was unused -- they follow an auxiliary. With is/was/has/have added and the ratio argument extended to verbs, `held` reads 277 auxiliary contexts against 37 determiners. Sweeping both ratios rather than one also moved the chosen adjective share, since the old pick was dominated once verbs worked: **51.1% of known errors at 2.9% cost becomes 68.2% at 2.1%**. Objects that cannot be objects fall 6.8% to 3.0% across the bench |
| **Khora can be told a rule now, at runtime, and use it -- eight modules were built and never run** | An audit against `khora_main.cpp` found ribosome, synapse, governor, retina, telos, logos, descent and taxis built, tested and never invoked by the live binary. `logos` was the widest gap because what it replaces is still in service: `Ligature::deduce` has exactly two inference patterns and both are written into the C++. Wiring it needed a second missing piece -- the Ligature could answer "what does X cause" and not "what is in here", so `Ligature::all` now returns the whole graph. **14,544 triples become 377 at a support floor of two**, and the two hardcoded patterns are installed as ordinary clauses alongside a third the old loop could never state. Live: `ask is-a man ?what` returns animal, being, thing, creature, descendant, fellow -- then `rule mortal is-a ?x mortal is-a ?x animal` and it returns a seventh, **`mortal [by mortal]`**, derived from a rule given at the prompt |
| **Khora notices when an act never pays -- 90% against a deterministic 80%, on the live system** | Volition scored every act as drive-pressure times an affinity a human wrote down, so Khora could be told an act serves Curiosity and never notice it had not paid once. The blocker was that there was no reward and the obvious ones are circular -- relief is computed FROM the affinity, and knowledge growth collapses five drives into "always study". What is observable, uniform and independent is whether the act produced anything: a rumination that concludes nothing yields 0, a study pass yields 1 only if the vocabulary grew. The dominant drive is the CONTEXT so the homeostatic rotation survives, and the learner chooses within it. Over 100 live acts each: fixed **80% every block, deterministically**; learned 75%, 75%, then **90%, 90%, 90%** -- half the wasted acts removed |
| **And the table says exactly what the hand-written affinities were getting wrong** | Watching the FIXED policy: under Curiosity it chose `dream` four times per twenty for a mean yield of **0.00 (4 tries)** while `ruminate` returned **1.00 (12)** -- and `study` was never chosen once, because no affinity reaches it. The learner tries every act once per context, which is how it found `study` at all and also how it learned `study` yields nothing here either. Neither fact was discoverable before. It does not reach 100% because UCB1 keeps re-trying the barren arms, which is the price of being able to notice if one ever starts paying. Volition also gets its first test in 13 checks |
| **A picture, a sound and a word in ONE memory -- 100% retrieval, one example, zero training** | Khora encodes an image, a sound and a word all to 10,000-bit Glyphs. Three unrelated front ends, one type out. That was an argument for eleven versions and nothing had put the three in the same container. `khora::chiasm` stores `bundle over fields of bind(role, value)`; bind is XOR so it inverts exactly. On 50 concepts stored ONCE each, all four directions retrieve 50/50 where chance is 1. On real front ends at N=200 (chance 0.5%): a picture with fresh noise it never saw returns the right word **100%** of the time, a word returns the right picture **100%**. CLIP buys the same shared space with 400 million paired examples and a training run; here it is the same 10,000 bits by construction |
| **The nearest rival, not the mean -- and it says the memory was never the problem** | Shifted pictures retrieved at 33.5% and jittered sounds at 27%, and the mean inter-concept similarity hid why completely. Retrieval is decided by the NEAREST wrong candidate: sight-with-noise scores 0.878 against a nearest rival of 0.750 (**gap +0.128**, and it works); sight-SHIFTED scores 0.621 against 0.750 and sound-jittered 0.521 against 0.737 -- **negative gaps**, meaning a different thing resembles it more than a fresh instance of itself does. The retina binds absolute position and this ear cannot separate chords sharing tones. Both are front-end limits, now quantified. One fix fell out: silence was being bound and bundled in, so every sound shared a term with every other wherever both were quiet -- dropping empty bands took unrelated-sound similarity from **0.484 to 0.328** |
| **The fundamental constant, measured twice independently** | How much fits in one glyph decides everything above it and nobody had measured it. `substrate_bench`: recognition against 500 distractors is 100% to M=128, **96.2% at 256, 68.0% at 512, 31.0% at 1024**, with measured similarity tracking sqrt(2/piM) to four decimals. `chiasm_test`, written separately, on fields per record: 100% at 128, **87.5% at 512, 42.5% at 1024**. `analogy_bench`: margin is about **3000/S bits** for S superposed pairs, and a thousandfold increase in candidates costs only about two slots. Crossover is roughly D/20 to D/10 items per glyph |
| **Three claims I made, and how each was wrong** | **"Analogy is arithmetic"** -- false as stated. `bind(bind(king,queen), man)` over independent random glyphs hits 1 time in 1000, exactly chance, because nothing in the construction ever said man->woman. The real claim is narrower and holds: when both items are COMPOSED over shared roles the cancellation is exact and one example gives **1000/1000 against 10,000 candidates**. **"Degradation is linear"** -- false about the shape; similarity falls linearly by definition (Hamming distance IS the flip count) while retrieval is flat then cliffs: 100% at 47% corruption, 0% at 50%. **"Federated merge is free"** -- lossy (96.5% vs 99.99% for one central pass) and **not associative**: three sites give 0.48/0.63/0.60 by grouping order, and majority carries no multiplicity so a site with 8 observations outvotes one with 256 |
| **A program retrieved by looking at the problem -- 84.4% correct, 23,000x cheaper than deriving it** | Khora synthesises certified programs and binds anything to anything, and those two had never met. Shown a task it has never seen, it now hands back a program WITHOUT searching -- unbound, not generated. Unfakeable to measure: the retrieved program is EXECUTED on the new task cases. The precondition was checked first, because two samples of one function have completely different inputs: naive encoding clusters at gap +0.131, describing the TRANSFORMATION instead of the values at **+0.557**. Then eight families, each solved once by search: naive retrieval runs correctly 31.9%, structural **84.4% (135/160)**, a randomly chosen program **15.0%** -- measured, not assumed at 1/8, because several families agree on some inputs. Synthesis 30.1 ms per program against retrieval at **0.0013 ms**, and what comes back still carries its proof state |
| **It gets faster at programming the more it programs -- 5.05x, and the solved count is identical** | The loop: try to remember a program, RUN it on the task cases, search only if it fails, bind whatever search produces. Verification is what makes this safe rather than clever -- a wrong guess costs one execution and then the same search that would have run anyway, so the claim is not that retrieval is reliable but that **retrieval is free to be wrong**, which is why 84% suffices where a cache would need 99%. Over 120 tasks: search-every-time 3362 ms, remember-first **665 ms**, both solving 120, with 21 wrong guesses caught and paid for. Cost per task falls from **17.0 ms in the first window of twenty to 1.9 ms** as the memory fills -- a total alone could not tell that from a cache that was warm from the start |
| **The live system remembers a program across restarts -- and the first attempt failed silently** | `synth` now tries to remember before it searches, and runs what it remembers on the caller's own examples first. A separate process, given a reverse task with different numbers and a different target language, answers **REMEMBERED** with no search. The first version failed its first restart for a reason worth keeping: a glyph is not a program, so something must hold the programs, and I keyed them off the techne Library -- which is BUDGETED and prunes. The label was bound in the memory and evicted from the archive before it was written, so the next process retrieved a label it could not resolve and searched **silently**, looking exactly like a memory that was not working. The program store is now its own and never pruned |
| **The textbook way to put a tree in one vector is wrong at depth three, exactly** | Nested role-filler binding reads a path by unbinding roles in order. It does not degrade -- it is an identity bug. `LEFT` and `RIGHT,RIGHT,LEFT` have similarity **1.0000**, literally the same bits, because XOR is involutive so a path is only its PARITY; and `LEFT,RIGHT` vs `RIGHT,LEFT` is 1.0000 too. At depth 3 it answers with the depth-1 leaf **98.4%** of the time, with full confidence. A per-(role, level) tag fixes both and was already in the algebra: depth 4 then reads **98.2%**, depth 5 74.5%, depth 6 gone. Size is free -- 100% at a fixed depth from 4 leaves to 128 -- and structure is real: the two parses of (a+(b*c)) score 0.1218 where a bag-of-symbols encoder scores 1.0000 on every shape |
| **I called holographic privacy a strength; the algebra has it and this code does not** | Against the stated threat model it holds cleanly -- an adversary with the record and the whole codebook but no role glyph lands **exactly on chance** at every width, and with the role recovers **100%** against 0.78%. Two practical breaks. The secret is an English word: `role_glyph()` is `from_hash(role_name)`, and a 24-word dictionary recovers **100% of roles and 100% of (role, value) pairs**. from_hash exists so archives survive a restart, which is exactly why it cannot be secret -- stability and secrecy are one property with the sign flipped. And XOR is a one-time pad with a reused key: XOR two record groups sharing a role and the role cancels, handing over the value pair **100% from a single record per group**. Inherent; no key entropy helps |
| **Immune to catastrophic forgetting -- but a std::vector is too, and the design that actually bundles is not** | The prototype memory holds **100.0% retention across 10 tasks and again across 40 tasks / 160 classes**, where the sequential MLP loses 28.5 to 79.4 points against its own joint reference of 100.0%. Then the deflation: 1-NN storing every example retains **95.6%**. Non-overwriting storage buys the retention; hyperdimensionality buys constant size per class, not immunity. And the fixed-memory single-glyph design **does forget** -- 100% to 38.6% over 10 tasks, 9.5% over 40, margin decaying +0.070 to +0.003. The agent discarded its own first experiment first: independently drawn task centres meant the tasks never competed and the MLP kept 100%, a benchmark on which the failure cannot occur |
| **An audit against the FIELD, not the repo -- four total absences** | Grepping for the mechanisms that define modern AI: **adversarial search** (MCTS, minimax, alpha-beta, game tree) zero hits; **causal inference** (intervention, counterfactual, confounding) zero hits; **sequential RL** (Q-learning, TD, value iteration, policy gradient) zero hits -- telos is a bandit with no state and no credit assignment over time; **self-supervised learning** zero hits. "Attention" appears three times, all of them the word in prose. Khora can plan over its own knowledge graph and cannot play a game, cannot learn from a reward that arrives three steps late, and cannot tell seeing from doing |
| **Seeing is not doing -- and the causal edges the planner uses had never been tested** | The Ligature holds 2,841 CAUSES edges from real books; `deduce` chains them and `plan_to` searches backward over them. Nothing in the extractor distinguishes causation from co-occurrence. Built the capability on data where the truth is known: with a confounder driving both variables, association reports **+0.639** where the true interventional effect is **+0.002**, and the backdoor adjustment recovers **+0.003** from the same observational data -- while still reporting +0.801 in a world where the cause is real. Then the real graph: causal pairs co-occur at **20.2% [18.8, 21.7]** against **1.6% [1.2, 2.1]** for the same words re-paired at random, so the edges are genuine associations |
| **And the clean-looking result in the same bench turned out to have no power** | Zero of 2,841 causal edges are asserted in both directions, which reads as proof the graph carries direction. It is not evidence. A degree-preserving shuffle expects **2.00** reciprocal edges by chance, so observing zero has probability **0.136** under the null -- NOT significant. I first wrote "the null is above one, so zero is a real signal", which is wrong: at a mean of two an honest coin gives zero one time in seven. The bench now computes the Poisson tail and says so. The graph may carry direction; this corpus is too sparse for reciprocity to show it |
| **A tie-break was a policy, and it inflated a result I published the same day** | `Valuer::choose` and `best` selected with a strict `>`, so among equal candidates the first REGISTERED always won. In a gridworld the bandit came out **identical to an "always go up" control to three decimals** -- 96% of its states ended tied and "up" was action zero. In Volition it was a silent preference for whichever act was registered first. Fixed by reservoir sampling over ties, with the randomness DERIVED by hashing (context, action, tie index, evidence) rather than drawn, since a mutable RNG in a const method is a data race and would make two identical queries disagree |
| **Which withdraws the 90% I reported for learned act selection** | v0.123.0 claimed the learner converging to a steady 90% against a deterministic 80%, "half the wasted acts removed". After the fix, identical protocol: blocks of **70, 85, 90, 70, 100** for 83/100, against 80/100. The total barely moves; the **clean convergence does not survive** -- it was the deterministic tie-break making the policy stable, not the learner settling. 83/100 [74.5, 88.8] against 80/100 [71.1, 86.7] overlaps, so the difference is **not demonstrated**, and both policies are reproducible byte-for-byte so more runs of this protocol cannot separate them |
| **Sequential decision making: the bandit reaches the goal 0 times in 20** | 32-state cliff-walk MDP, Q-learning and SARSA against value iteration on the known model, greedy policies scored by exact policy evaluation. Q-learning closes **100.0%** of the gap to optimal (96.4% policy match, 20/20 goals); the `telos::Valuer` Khora actually uses closes 74.7% -- **identical to an always-up control to three decimals**, so the learning contributes nothing measurable to return -- and reaches the goal **0/20**. On delayed reward only 0.51% of its 3.3M transitions carried any reward, and its policy is correct on 2 of 25 squares. At gamma=0 the MDP IS a bandit and it is exactly optimal at 100%; it falls the instant gamma leaves zero. There is no slot in a (context, action) table for the value of a successor state |
| **Attention, hand-written and TRAINED, tied with the substrate and then beat it on capacity** | No attention mechanism existed in the tree. Built scaled dot-product attention with the backward pass checked against central differences (worst relative error **3.5e-10**), reported at three configurations so a bad training run cannot pass as a limit of the mechanism. On associative recall to n=128, trained attention and the single-glyph bundle are BOTH at 100% -- a tie. Pushed further, one 1,256-byte glyph holds about **256** pairs at ceiling and is at 42.5% by 1024 while the hand-set head stays at 100%: **attention has capacity the bundle does not**. The substrate wins on cost -- 7,168 trained parameters against **zero**, 1,256 bytes against 131 KB, a flat 7us query -- and on bidirectionality: from ONE write chiasm answers both directions at 100% where trained attention runs 99.8% forward and **0.8%, exactly chance, reversed** |
| **Khora cannot play a game -- and win rate against a weak opponent proves nothing** | No MCTS, minimax or alpha-beta anywhere. Connect-4 with alpha-beta and UCT, on a 5x4 board **solved exactly** (2,516,078 positions; the game is a draw) so agreement with optimal play replaces win rate. Every agent including a one-ply heuristic scores **at least 94.8% against random**; agreement with exact play separates the same agents from 39.5% to 100%. Alpha-beta is far cheaper per unit of strength -- **28 nodes and 3us** beats the greedy heuristic 99.2% -- but MCTS scales better, and uct-10000 is the only method that got close to exact play (93.3% agreement, 31.2% against perfection) |
| **And alpha-beta is not monotone in depth, which is the most useful thing in that table** | Depth 6 draws 18.7% against perfect play where depth 2 draws 27.7% and depth 8 draws 36.0%, reproduced at 100 and at 300 games. The deeper control rows converge steadily toward exact play, which identifies the culprit: the search is correct and the **evaluation** is wrong -- it scores a three-in-a-window without checking the fourth cell is reachable, and deeper search optimises harder against that lie. The weights were NOT retuned; tuning until depth 6 looked good would have deleted the finding. The ranking is also **not transitive**: depth 6 is the strongest alpha-beta against 10,000-rollout MCTS and the weakest against both the greedy baseline and exact play |

## Build

The Visual Studio generator documented in older revisions of this file **does not
work on this host** — the VS Installer was removed, so CMake cannot resolve the
Build Tools instance. Use the task runner, which activates MSVC directly and
builds with Ninja:

```powershell
.\tools\khora.ps1 all          # configure + build + test
.\tools\khora.ps1 bench        # throughput numbers
.\tools\khora.ps1 run khora    # the REPL
```

See [docs/DEVELOPMENT.md](docs/DEVELOPMENT.md) for the full task list, the
toolchain layout, and why the runner is necessary.

Requires the MSVC v143 toolset, a Windows 10/11 SDK, CMake 3.20+, and a CPU with
AVX2 (Haswell+ / Excavator+) — `KHORA_USE_AVX2` is ON by default with no runtime
fallback.
